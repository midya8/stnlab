# Exact temporal consequences, not a calendar commitment

## Contract

Input has exactly `nodes` (integer 1..6) and `edges` (list of at most 12 integer triples `[u,v,w]`, valid node indices and weights -20..20). Ck denotes the kth original directed constraint `t[v]-t[u] <= w`. Parallel edges, duplicate constraints and self-loops retain separate original indices. No implicit nonnegative-time rule, deadline, duration, capacity or objective. All times are real-valued. Fixing t0=0 removes a shared translation and does not constrain any difference. Integer inputs admit integer certificates; this does not assert that time is discrete. Inferred bounds and witness values can exceed the input weight limit.

`analyze(data)` returns exactly schema,input,consistent,schedule,matrix,pairs,removals,negative_cycle. Schema `stnlab-v1`. Every report is deterministic for its original input order.

If inconsistent: schedule/matrix are null, pairs/removals are empty, negative_cycle contains original edge indices in directed cycle order and their negative integer sum. The witness is a simple directed cycle, canonicalized to its lexicographically smallest rotation; the lexicographically smallest such negative cycle is selected. No claim of smallest cardinality or most-negative cycle. Summing its inequalities cancels the time variables to `0 <= negative`. No finite bound or redundancy result is returned for an empty feasible set, avoiding vacuous implication or a meaningless Floyd matrix after negative-cycle detection. Any component can invalidate the network, including one unreachable from t0.

If consistent: negative_cycle is null. Matrix D[u][v] is the strongest implied upper bound on t[v]-t[u], or null for no finite upper bound. Diagonal is zero. Pairs are row-major, one record per ordered pair with u,v,bound,path,schedule,ray. A finite pair has a lexicographically first original-edge-index sequence among all shortest simple paths; for u=v this is the empty path. Path order is not fewest hops. Its complete anchored schedule satisfies every original constraint and attains the bound exactly. An unbounded pair has null path/schedule and an anchored ray. Different pairs can use different schedules; endpoint combinations need not be jointly feasible.

The shared base schedule is the implicit zero-super-source shortest potential, normalized at t0. Every finite-pair witness is the same construction after adding `[v,u,-D[u][v]]`, which forces equality at that pair. This added edge cannot make a consistent graph inconsistent: every returning original path from u to v has weight at least D[u][v]. Adding it imposes the lower inequality equal to the already-implied upper bound. Synthetic witness-construction edges are internal and may exceed the public input weight limits; they are not original-index proof-path edges.

For an unbounded pair u,v, let R be the nodes reachable from u. Before anchoring, ray[j] is 0 in R and 1 outside R. No original edge leaves R, so every edge's ray difference is nonpositive. Subtract ray[0] from every component to keep t0 fixed; differences do not change. Since v is outside R and u is inside, ray[v]-ray[u]=1. Base + k*ray satisfies all edges for every real k>=0 while the selected difference grows without limit. The report proves unboundedness, not merely a failed finite search.

Removals are in original edge order. Each record has edge,redundant,bound_without,path,counterexample. Remove only Ck, retain all other original edges. It is redundant exactly when their shortest u-to-v bound exists and is <= the removed w. A redundant record gives the corresponding path using original indices, never Ck; a nonredundant record gives a complete anchored counterexample satisfying every remaining edge with removed difference >= w+1. It is generated by adding the reverse constraint `[v,u,-w-1]`. With integer weights a finite remaining bound >w is >=w+1, so the added edge remains consistent; if no path exists it cannot close a cycle. This is a one-edge implication audit, not a simultaneous simplification algorithm. Two identical edges can each be redundant while their joint removal changes the feasible set. Nonnegative self-loops are redundant via the empty path; negative self-loops are inconsistent.

## Three implementations and independent checks

Native generation: synchronous Floyd-Warshall closure with explicit None for infinity, initial min over parallel edges and zero diagonal. A fresh previous matrix per intermediate node prevents iteration-order ambiguity. Negative diagonal detects inconsistency anywhere. DFS selects the documented path/cycle ties. Synchronous Bellman-Ford with all initial potentials zero constructs base and augmented-network witnesses; an extra inequality check rejects any failed construction. Native generation never uses oracle.py.

Native verification: oracle.py enumerates vertex permutations and products of original edges for each adjacent vertex pair. It derives every simple path distance and lex tie independently of Floyd, every simple directed cycle independently of generator DFS, and super-source potentials as the minimum over zero and every enumerated source-to-node path. It repeats this on each augmented or one-edge-removed network. `verify` recursively compares exact keys, types, lengths, order and values against this independent complete report. Booleans are not integers. No generator entry point, Floyd, Bellman-Ford, canonical-path or negative-cycle routine is called; tests disable them during verification.

Browser: recursive path-prefix exploration from every start computes all simple path minima and negative cycles. Unlike native oracle permutation/edge products, it expands only available outgoing edges. Schedule potentials are obtained from this recursive distance matrix, not native Bellman-Ford. It does not fetch native reports, execute Python, use a model or make an API call. Full native/browser reports are compared. None of the implementations imports NetworkX, Z3 or a third-party solver. Standard algorithms and mathematical results are attributed below; code and synthetic controls are original. Strict JSON/atomic CLI pattern and browser-test startup helper were adapted from this portfolio's HallLab, not from a published solver.

## Numeric and scope limits

Public weights are small integers; all calculations and JSON outputs are exact integers or explicit null. JS numbers remain exact at these small bounds, including the internal finite witness augmentations. No floating tolerance or finite sentinel for infinity. Native input is UTF-8 <=65536 bytes; report verification <=8MiB. Duplicate JSON keys rejected; booleans and floats/exponent spellings rejected where integers required. Browser JSON.parse has last-key-wins and numeric lexical normalization, so browser acceptance is not identical to native strict CLI acceptance. Native outputs use atomic replace and no partial output on input/verification failure.

Classical STN consistency is polynomial, but exhaustive simple-path/cycle certificates/checking are intentionally restricted to tiny graphs. Do not infer production scaling from this implementation. No resource constraints, scheduling objective, conditional/disjunctive constraints, uncertain-duration STNU, dispatchability, real-time execution guarantee, real calendar/account actions, learned model, private data or paid API. This is feasibility and consequence reasoning on a supplied network, not finding actions or deciding which constraints a person should accept.
